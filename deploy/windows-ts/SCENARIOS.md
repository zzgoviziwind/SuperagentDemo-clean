# Windows 安装与运行映射

基线 `7b7587d14399659d7951d3e195af863514fbf118`。界面以 `.rewrite-oracle/apps/web` 中包含「现场记录」的 React 快照为准。

| 原入口 | Windows TS 对应行为 | 验收依据 |
| --- | --- | --- |
| `deploy/start-local.ps1`、`start.ps1` | 用户级解压安装后启动随附 Node 24，后端与工作台共用回环地址 | 实际监听地址、PID、`/health`、首页与静态资源 |
| `deploy/start-preview.ps1`、`stop-preview.ps1` | 验收使用独立目录、随机回环端口和离线替身入口 | 可以重复、无真实账号和渠道、诊断定位自己的进程 |
| `deploy/stop.ps1` | 停止前核验 PID、创建时间和可执行文件，停止后等待退出 | 端口被占时拒绝接管，重启时更换 PID 并保留数据 |
| `deploy/state/service.json`、`stdout.log`、`stderr.log` | `Status` 和 `Diagnose` 读取本地状态，新增按启动轮次划分的日志 | 正常运行、停止、陈旧记录、端口冲突及启动失败可区分 |
| `deploy/backup.ps1`、`restore.ps1` | 安装目录按版本保留程序，数据单独存放。升级、回滚均在兼容的数据代内切换 | 升级后能读写同一份临时数据；回滚仍使用升级后的数据。跨代拒绝，数据备份和业务迁移独立验收 |
| `login-codex.ps1`、飞书检查脚本 | 后端和插件的独立接入验收 | 本轮只使用离线入口和合成数据 |

## 独立验收场景

1. 使用带空格及中文的临时用户安装路径，运行两份含相同快照工作台、不同后端版本的自解压 EXE 和备用 ZIP。安装后执行 `Status` 和 `Diagnose`，请求 `/health`、首页、打包资产及 `/field-timeline.example.json`，确认运行的是随附 Node 24。
2. 用离线替身在 `SUPERAGENT_DATA_DIR` 写入合成计数。重复安装相同版本保持 PID；重启后 PID 更换且计数连续；停止后本实例端口释放；再次启动仍可读取计数。
3. 启动期间尝试第二次操作，确认同一安装目录串行化。制造端口占用，确认拒绝启动且原进程继续应答。校验损坏包在切换前被拒绝。
4. 从第一版升级至第二版，核对实际 HTTP 版本和跨版本读写。回滚时保留第二版写入，再回滚应能切回第二版。启动失败的候选应留下诊断日志并恢复运行中的原版本。数据代不同的包应在停服务之前被拒绝。
5. 用项目 Playwright 分两轮运行快照原工作台，在桌面、平板、窄屏检查现场记录入口、表单和现有导航，查看截图并按实际数据写明覆盖。安装替身验证、隔离预览和总控 TS 服务联测分别记录。
