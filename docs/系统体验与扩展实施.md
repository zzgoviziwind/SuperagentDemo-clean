# 系统体验与扩展：首批实施记录

2026-11-15，基于当前工作树，非部署验收报告。

## 产品方案和本轮实现

入口“系统如何工作”：八种场景，逐步展示输入、规则、输出、分支和实现入口。演示与真实事件共享步骤名称：接收、识别与分派、处理与核验、回复与收尾。演示拒绝/取消会停止，不伪装成功。

真实事件新增“现在需要做什么”：目标、状态对应操作、阻断原因、完成条件、发送计数、等待条件。不编造预计完成时间。保留来源和产物，原始字段、路由历史和诊断下沉。任务失败、暂停、等待输入/资源、未知结果时自动展开既有操作面板。

修复发送状态读取：真实接口返回 record.result.write_status，原页面部分查顶层字段可能误报未发送。仅 succeeded 算已确认，不以 completed 或草稿获批替代。

本轮没有重写所有页面。真实恢复仍复用原接口，保存补充与显式恢复是两步；演示合并按钮仅用于教学。尚无未路由事件自动追问闭环、计划版本表、预计耗时、统一接入向导和通用工作流编辑器。

## Router、Worker和规则位置

工程判断在 ingestion._route_impl：去重、身份、唯一项目、角色/request授权、响应策略、回声、输入类型、只读/写冲突、私人暂停/静默、显式订阅、问题编号/回复引用。semantic_routing_enabled 默认 false；普通私聊及明确关联可跳过模型。

语义提示词：semantic_routing.INSTRUCTIONS；输入：enqueue_if_enabled；真实快照：SemanticRoutingJob.context/output。正文20000字符、最多100条查询后授权任务（目标1000字符）、最近20条摘要（各2000字符）、最多100条订阅。输出 action=create/dispatch/ignore/confirm，kind=reply/analysis/repair，task_id/state_version/reason。180秒超时；异常待核验。confirm不是自动追问，审批是独立机制。项目 Router 是讨论入口，不是事件分派器。

Worker是任务执行身份和会话入口，不是额外常驻Leader。Scheduler管理每轮客户端；Task可多轮，通常复用thread，旧分析线程缺工具绑定时新建。提示词在 scheduler.run：角色/JSON要求 + goal + 验收标准 + 只读约束或测试命令 + 补充/协作结果 + 最近50条来源（各3000字符）+ 协作规则 + 附件；图片独立传入。reply_worker只输出回复正文。

主Worker可请求最多3个只读子任务，工程收集结果回流，不递归。只有可拆分调查才值得使用，增加会话会增加费用、延迟和证据归属复杂度；当前不需要再增加Leader。

## 可配置流程方案（尚未实现）

默认流程保持处理→证据核验→人工验收→可选回复→来源核验，高级模板才添加复现、Review、部署。每阶段持久化模板版本、前置条件、输入引用、产物、验证器、审批、状态、尝试次数、外部action_id和恢复依据。工程验证器推进，提示词指导方法，模型不能自行宣布关键阶段通过。

|建议阶段|必要证据|暂停和恢复|
|---|---|---|
|复现|基线、复现步骤与结果|缺信息补充后重验|
|修复|隔离工作区、范围、差异|未知写入先对账|
|OCR Review|固定差异版本、评审输出|修复后重新评审新版本|
|测试|配置命令、退出码、输出|失败后修正，不能复用旧版本测试|
|部署/生产发布|不可变产物、目标环境、明确审批、动作账本|无授权暂停；超时核对目标，不能盲重发|
|发布验证|实际服务与业务检查|失败人工处置，不自动猜测回滚|
|来源回传|明确目标、正文/状态动作、授权|独立账本核验后决定重试|

模板变更仅影响新任务；运行中迁移需显式预览、保留历史、作废受影响审批。现有private_event_rules是接收/重路由策略，不是流程引擎。首批不做通用拖拽编辑器，避免为不存在的执行阶段制造假配置。

## 平台扩展：本轮边界与剩余耦合

新增 connectors/capabilities.py，集中来源名、项目绑定字段、事件类型、接收模式、回复/状态能力。ingestion消费此声明。注册不授予权限，不启动连接，不授权发送。

尚未达到“新增平台不改核心”：ingestion仍有钉钉策略、私聊和引用；Project平台字段、governance身份、semantic_routing来源检查、connections构造、delivery发送、前端筛选仍有耦合。必须明确保留此限制，不能只换平台名称就宣称插件化。

目标边界：适配器负责认证引用、只读健康检查、标准化、引用解析、平台发送；核心负责统一身份授权、事件去重、任务和流程、审批与账本。后续用SourceBinding替代Project平台数组，使用通用用户/会话/问题引用，兼容旧路由键以防重复建任务。

新增平台需要：

1. 脱敏能力和配置元数据，秘密仅环境变量名或凭据引用。
2. check只读，区分未配置/认证失败/权限不足/连接失败，不发送测试消息。
3. normalize输出稳定external_id、actor_id、thread_id、project_external_id、event_type、正文、附件；正文不能决定身份和路径。
4. emit持久成功后才推进游标，支持分页重放。
5. 写操作使用common.py的AuthorizedAction和ActionLedger，审批先于调用，超时unknown不重派。
6. 验证重复ID、跨会话ID、缺身份、项目歧义、撤权、过期版本、游标恢复、发送超时、审批重放与脱敏。

最小示例OfflineExampleAdapter不联网、不写入，测试验证稳定ID和会话隔离。它未注册生产来源，因此只是契约示例，不是完整新平台接入。当前适配器尚未全部实现该Protocol。

下一批接入页面应统一能力卡、准备清单、只读检查和脱敏修复建议；真实发送测试独立提供目标/正文/授权确认。首批复用管理设置，未完成接入向导。

## 验证分层

演示：虚构数据、本地交互。自动化：前端组件和离线后端集成。真实接入：本轮未执行钉钉/Redmine发送、真实模型、部署或业务数据库修改。自动化具体结果见最终交付说明，不把演示成功算真实业务验收。
