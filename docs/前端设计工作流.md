# SuperAgent 自主前端设计工作流

此工作流把设计决策、实现依据和浏览器反馈连成闭环。用户描述业务目标，Agent 自主处理通常的视觉决策；项目规范保留跨任务的一致性。

## 原理与职责

1. **理解现状**：先读项目规则、DESIGN.md、目标页面与接口，识别主要用户操作和不可改变的行为。
2. **研究并决策**：新模块或明显改版才访问 3–5 个真实参考；frontend-design 将业务目标转为布局、信息层级和设计 Token。局部修复沿用已有身份。
3. **工程实现**：modern-web-guidance 按实际能力检索现代 Web 指南，约束兼容性、语义、焦点与性能；它不替代设计判断。
4. **形成反馈**：Playwright 启动当前源码和隔离后端，执行真实浏览器操作，产出截图、页面指标和 trace；Agent 必须打开截图，以 Impeccable 的层级、一致性、认知负担和状态反馈等标准审查。
5. **修复与复验**：只修复授权范围的问题，第二轮重新操作、截图和审查。无问题时不强行修改，未解决项如实保留。
6. **沉淀**：设计决定进入 DESIGN.md；问题—修改—复验写入验收记录，后续任务复用。

这里没有“安装技能后自动变好看”的保证。技能提供决策方法，DESIGN.md 提供记忆，浏览器提供真实证据，迭代把偏差反馈给实现。像素差异只能判断与基线是否不同，不能判断设计是否优秀；首次截图须先经实际审查，不能盲目更新成合格基线。

## 本项目边界

优先保留事件、Worker、项目设置、管理设置、来源消息与渠道回复的功能和接口。当前是已有产品，按 Operate 模式检查，不因缺少 PRODUCT.md 就启动重设计或产品访谈。产品事实继续以 README、实施基线和接口契约为准。

不启用真实 8765 服务、已有 8876 预览或真实渠道来执行本套自动测试。固定启动独立 8877 后端和 5177 前端；端口已占用时报错，不复用未知进程。现有 Vite 配置不变，专用启动器仅在测试进程内覆盖代理。

后端复用 `deploy/preview.py`，数据库为 `.test-tmp/design-workflow-preview/preview.db`；数据为模拟事件，调度、路由、看门狗与发送开关关闭。测试通过 API 复查这些开关，浏览器拦截非读取 API 操作，页面中不点击启动、发送、保存、审批等操作。

## 运行

项目根目录 PowerShell：

```powershell
npm.cmd --prefix apps/web ci
npm.cmd --prefix apps/web run test:visual
```

需要项目 `.venv` 中的 Python 及现有后端依赖，Node 22，已安装 Microsoft Edge。Playwright 使用 `channel: msedge`，本套配置不下载另一份 Chromium。若切换浏览器，显式修改配置并另建截图基线，不能沿用原验收结论。

测试进程由 Playwright 的 webServer 生命周期管理；正常完成或失败后清理其创建的服务。不要手动停止其他现有服务。Windows 首次运行需要允许浏览器、测试子进程与本机回环通信。

## 实际覆盖

三种视口：1440×1000、1024×900、390×844。共六个测试实例：

- 事件列表 → 指定模拟事件详情 → 窄屏返回 → 空搜索 → 清空恢复。
- 项目列表 → 原生项目抽屉 → Tab 焦点包含与 Esc 关闭返回 → 管理设置 → Worker 工作台。

每个视口七张截图，正常一轮共 21 张。每次记录字体、背景、强调色、视口、整页宽度、URL、浏览器版本，并保留 trace。页面 JavaScript 错误、API 失败、意外写入及整页横向溢出均使测试失败。

这不是全业务验收：不覆盖真实渠道、真实模型、任务执行、数据写入、审批发送及完整异常状态。减少动画后截图不等于动态效果验收；移动视口不等于真机验收。

## 查看、审查与第二轮

- 每次启动打印本轮证据目录 `.test-tmp/design-workflow-visual/<UTC时间>/`；各轮独立保存，避免与其他会话的默认 test-results 目录互相清理。
- 截图与 trace 位于该目录的 `results/`，HTML 报告位于 `report/index.html`。
- 在前端目录查看：`npx.cmd playwright show-report <本轮证据目录的绝对路径>/report`。
- 不覆盖前轮证据；如临时结果被其他清理操作移除，HTML 报告的附件仍可作为该轮截图与 trace 的依据，应一同归档。
- 打开桌面、平板、窄屏关键截图，结合 trace 核对：主要操作是否突出、状态是否清晰、长中文是否截断、内容是否可达、抽屉与焦点是否正确、空状态是否可恢复。
- 第一轮记录问题、证据、优先级与是否属于本次范围。改动后运行受影响单元测试和截图测试，再打开第二轮截图复查。
- 未改 UI 的接入任务也执行第二轮验证稳定性，不用凑轮次改页面。遗留问题应记录为未解决，不能把截图测试通过写成全页面视觉合格。

## Impeccable

用户目录已安装 `frontend-design`、`modern-web-guidance`、`impeccable`，不复制进仓库。运行设计任务时按需读取这些技能；在当前项目目录调用 Impeccable 的 `context --target apps/web/src/main.tsx` 确认上下文。

需要机械扫描时使用安装技能中的 `impeccable.cmd detect --json`，并显式传入本次文件；不得使用 `--changed` 混入其他会话的大量改动。扫描不自动修复页面，不替代截图审查。本次不添加自动 hooks、live 服务或改动全局配置。
