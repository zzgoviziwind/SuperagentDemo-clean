## 已做到的能力

1. **事件和任务是持久对象。** 区分收件、路由、执行、事件是否解决及渠道交付；同一来源的订阅扇出按目标回查。两级判定、订阅直达和隔离 Worker 与 DeepSeek 对应思想等效，功能不依赖同一个全局 Router。
2. **高风险副作用有明确边界。** 动作哈希、任务修订、审批、渠道账本、节点租约都用于阻止误操作或迟到结果。相对于所查 DeepSeek 原型默认的操作系统用户全权限模式，本项目在本地审批和写入边界上有更细的明确约束；这不是全面安全结论。
3. **完成需要证据。** 工作区、差异、同轮测试和错误可被独立检查；验收时重新比对差异。只读子 Worker 的结果可回流但不替主任务宣布完成。

## 最大的五项缺口

| 缺口 | 可复查证据 | 后果 |
| --- | --- | --- |
| 调度、外发、API、巡检共享控制进程 | `scheduler.py:132–183`、`main.py:28–67,185` | 进程退出时全停；慢渠道还会推迟排队任务。静态健康不等于可执行。 |
| 持久状态能保留，但不能安全地自动续作 | H1/H9，`main.py:28–44,386–402` | 运行/审批启动时变为未知；旧审批被拒是正确保护，正常恢复仍依赖人。 |

## 决策建议

1. **定位：** 有 SuperAgent 特征的多 Agent 工作流，可靠性仍处原型阶段。已超出单次提示驱动的 Agent；部分自动启动和回复不构成无人值守运行。
2. **对标：** 已有等效的二层职责、规则/语义路径、订阅扇出、状态和角色隔离；具体审批及未知副作用防重比所查 DeepSeek 原型的默认部署更细。差距在后台 Job、按需召回、外部监督和真实代码平台闭环。
3. **包装和部分实现：** 可用的本地/远端执行路径均为 Codex，其他检测项不等于 Runtime 已替换；ChatGPT 项目自动创建及同步明确为 blocked；Watchdog 有独立模型会话但不是独立控制进程；PostgreSQL 配置不等于验证过恢复；人工验收不等于独立 Review。
4. **7×24 门槛：** 需进程外监督、持久作业与租约隔离、进展与时限、安全重试和不明结果处理、可恢复的上下文、可查询的回执及持续负载数据。
5. **只做三项：** 持久执行意图与回执；独立监督与有效进展；一条用真实模型、独立审查及真实回执验收的交付链。
6. **不要先做：** Agent 市场、复杂依赖图、自动合并/部署、多活集群。现有产品范围先验证一个控制器、一个节点和一条交付链。
7. **到 80：** 按 [P0/P1](improvement-roadmap.md) 分批将所有指标补到 L4，条件性增量 26.7；估计 30–50 工程人日，持续观察时间另计。
8. **到 90：** 在 80 基础上，至少再为 50 权重的一组指标建立 L5 证据。采用真实模型与隔离渠道、代表性负载、故障注入、备份恢复演练和至少一段业务周期的重复验证，指标和阈值事先约定。
