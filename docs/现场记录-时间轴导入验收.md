# 现场记录时间轴导入验收

在工作台「现场记录」选择项目和记录名称，上传时间轴 JSON 和同名关键截图，再点击「整理候选事项」。时间轴由外部工具准备，可在录入页下载 JSON 示例。转写和截图使用从同一时点起算的整数毫秒。截图可带 OCR 文字、位置和置信度。平台复用导入的 OCR 结果，整理阶段只把时间戳与文字交给已连接的 Codex。

审核时展开候选的「证据」，点起止时间读取原始转写片段，点截图编号打开带抽帧时刻的原图。通过人工审核后，事件中心的「消息」里仍可回看。当前的时间段指向导入转写原文，平台内音视频文件上传、播放和转写留到后续。

## 验收样本

从零生成的虚构交流，包含四段转写、四张截图和上轮实际 PaddleOCR 已生成的识别结果。没有真实患者数据。以真实 Codex 归纳得到以下三条，重复讨论的预览问题归为一条。

| 事项 | 转写片段 | 关键截图 |
| --- | --- | --- |
| 已录入科室小结在报告预览中未显示 | 00:08–00:17、00:18.200–00:32、00:51–01:01 | 00:11.800 报告预览、00:14 科室详情 |
| 导出清单新增最终审核时间 | 00:18.200–00:32 | 00:25.100 导出清单 |
| 刷新同步返回 504 且重试未成功 | 00:35–00:48、00:51–01:01 | 00:39 同步提示 |

隔离 HTTP 验收逐个校验所有引用转写读回值和截图原始字节。审批前现场事件数为 0，人工批准一条后只产生一条只读任务，分析结果尚未有时实施请求返回 409。

后端 32 项回归和前端构建通过。Edge 首轮在 1440×1000 和 390×844 检查导入、逐条打开原图、回看转写、Esc 关闭与焦点返回。首轮截图显示窄屏时间按钮和较长转写挤在同一行，改为独立按钮与单行预览，完整原文继续在弹窗中展示。复验在 1440×1000、1024×900 和 390×844 共通过 9 项。浏览器使用已保存的实际模型结果与样本原图重放，独立 HTTP 验收使用真实模型。两轮截图与轨迹分别保存至 `.test-tmp/design-workflow-visual/2026-11-18T08-07-55-114Z/results/` 和 `.test-tmp/design-workflow-visual/2026-11-18T08-10-50-007Z/results/`。

本次时间轴和模型输出分别在 `.test-tmp/field-timeline-live-r1/timeline.json` 和 `.test-tmp/field-timeline-live-r1/candidates.json`。原图在 `.test-tmp/field-ocr-benchmark/`。用项目 Python 运行 `tests/fixtures/field_organizer_live.py <原图和OCR样本目录> <新证据目录> --timeline` 可在独立数据库复现，使用当前本机登录进行文字整理。
