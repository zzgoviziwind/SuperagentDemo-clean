# SuperAgent 实施基线

日期：2026-11-13。用户要求并行完成六周工作包，由总控验收与返工。

## 本轮交付

个人／受信任小团队研发助手：钉钉 @本人或授权群内明确请求、Redmine 指派／评论变化 → 绑定项目目录和基线 → 独立工作区 → Codex 分析、修改、测试 → 展示证据、审批、验收 → 授权后回复原渠道。持续接收新消息并跟进原任务。

首版改为 Web＋钉钉＋Redmine＋Windows/Linux 本地 Codex。GitHub 适配为可选，默认不自动合并、上线、修复真实数据。业务恢复先交付方案，不混淆 Agent 自身恢复。此范围替代 v0.1 文档中 GitHub/Linux 优先、钉钉/Windows 后置的安排。

## 技术收敛

- Python FastAPI 控制服务，React/TypeScript/Vite 工作台。
- SQLAlchemy 持久化，开发默认 SQLite（单进程），部署 PostgreSQL；启动时迁移和恢复。不得把 SQLite 验收算作 PostgreSQL 并发验收。
- Codex app-server 作为执行引擎，以本地 stdio JSON-RPC 接入；独立配置可执行文件和工作目录。任务与 Codex thread/turn ID 关联。持续会话不等于副作用恰好一次。
- 接入器是独立后台服务，可禁用；DWS 消费结构化消息，Redmine 增量查询并持久化游标。默认不监听真实账号，用户配置后明确启用。
- 所有业务写入由确定性权限、版本与外部动作账本控制。先交付回复草稿；没有有效授权不自动发送。
- 项目绑定来源群/Redmine project ID、仓库目录、分支、构建测试命令和允许能力。工作目录不由外部消息任意指定。
- 按任务建立隔离工作区，检查原目录未提交修改，拒绝静默覆盖。运行目录和产物均做路径约束。
- 测试使用离线假 Codex 协议进程及假外部服务；单独记录真实 Codex、钉钉、Redmine 联调状态。

## 交付门槛

2026-11-14 产品修订将常规接入改为直接检测并连接本机已登录 Codex，消息策略分别控制私聊与群聊。每个模型分流事件进入真实 Router 会话，回复/分析/修复进入各自 Worker；共享摘要、人工复核、原线程续聊及可见历史都有持久证据。最新产品与真实会话验收见 [产品修订验收](产品修订验收-20261114.md)。

2026-11-14 补齐实现增加语义分派、多对多订阅、独立 Watchdog、共享卷执行 daemon 与客户端 MCP 桥接。仍以 Windows/SQLite 单控制进程为验收基线；ChatGPT 项目原生自动建聊没有已验证公共契约，MCP 客户端操作不等同于原生聊天同步。最新运行与验证状态见 [能力补齐验收](能力补齐验收-20261114.md)。

1. 真实持久 API 和可用工作台，不依赖前端假数据。
2. 事件幂等、来源关联、身份/权限验证、项目路径约束通过负向测试。
3. Codex 协议可以创建、补充、恢复、中断和接收审批/结果；状态持久化。

## 本轮事件中心产品基线

工作入口为统一事件中心，删除事件池。相关来源消息聚合为事件组，逐条保存核验结果；Task 仅作为兼容的内部执行聚合。Worker 可自行处理，也可提出有界只读协作请求，子 Worker 的结果以事件返回。显式跟进关系在事件组中维护，全局列表仅供查看。继续保留现有审批、隔离工作区、版本和未知执行结果保护。

## 2026-11-14 事件中心简化修订

只有外部消息和人工输入作为用户可见事件；内部执行、协作和状态变更作为诊断记录。默认展示来源、当前环节、交付结果；同组来源位于流程图之前。重复关联入口删除，详细路由和运行日志在末尾默认折叠。草稿、执行完成、实际发送与人工验收分别展示，不互相替代。

## 2026-11-15 自动工作与项目配置修订

用户选择自动交付模式后，当前版本通过核验的结果可依据持久策略授权发送，事件规则的人工审核、暂停和静默范围优先。自动发送沿用目标校验、版本检查和动作账本。连接配置保存并启用时立即尝试连接，运行状态显示缺少的配置项。

项目支持一个根目录下配置多个 Git 仓库和各自本地基线分支。Worker 在独立目录内按相同相对路径准备各仓库，统一保存基线、校验改动与生成产物。项目删除采用隐藏归档，保留编号和历史关联。目录选择支持本机目录浏览与已有 Codex 项目目录列表。

事件中心使用满高双面板、来源/状态/关键词筛选和连续加载。消息记录展示消息、关联消息和对应事件入口。原生 Codex 项目归属写入尚未接通，本机生成的 ThreadStartParams 契约未提供 projectId。
