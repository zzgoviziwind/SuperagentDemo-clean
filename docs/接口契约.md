# 模块接口契约

## 按任务类型配置 Codex

- `GET /api/v1/settings` 返回 `codex_task_profiles`，默认是空对象。管理员通过原 `PATCH /api/v1/settings` 保存。
- 支持 `semantic_routing`（事件分流与归类）、`router`（项目讨论）、`reply`（普通回复）、`analysis`（只读分析）、`repair`（代码修复）、`watchdog`（独立巡检）。每类接受 `model` 和 `effort`；字段缺省或为 null 时分别沿用 `codex_model` 和 `codex_effort`。
- 提交 `codex_task_profiles` 会替换整组覆盖项；提交空对象恢复全部全局设置。不提交该键则保留已保存的覆盖项。保存后的设置用于随后启动的执行轮次，包括续聊。
- 管理设置首页的「模型与推理强度」单独保存以上三个模型字段。`GET /api/v1/codex-prompts` 仅管理员可读，按上述阶段返回 `[{title,text}]`，展示当前代码实际使用的指令和带占位标记的任务模板，不返回历史会话或实际业务输入。

## 2026-11-14 事件与会话扩展

- `GET /api/v1/architecture` 返回实际架构能力、外部事件和引用关系计数；仅管理员。
- `GET /api/v1/events?routing_status=all` 可分页浏览全部接收状态。`GET /events/{id}/trace` 返回 `{event,attempts,subscriptions,task,deliveries,execution,live_stages,legacy}`。attempts 为历史路由记录；execution/live_stages 为关联任务当前证据，不能证明均由当前来源事件触发。
- `GET /api/v1/subscriptions` 返回 `{items,scope}`，item 含引用键、项目、目标任务及可读名称。旧引用仍一对一，新增 `subscription_type=explicit` 的线程订阅支持多对多，id 需与类型组合识别。
- `GET /api/v1/sessions?project_id=` 返回可访问会话数组；`GET /sessions/{id}` 返回 `{session,messages}`。ID 为 `worker:{task_id}` 或 `router:{project_id}`。
- `POST /api/v1/sessions/{id}/messages {content,change_goal?,expected_state_version?}`。Worker 复用任务消息控制；Router 未启用时记控制备注，启用后以独立 Codex 线程排队讨论。Router 内容限制 20000 字；仅管理员。
- `POST /api/v1/sessions/router:{id}/reconcile {evidence,expected_state_version}` 核验已退出但结果未知的 Router 运行，不自动重播旧消息。
- 设置新增 `router_agent_enabled`，默认 false。与 Worker 调度开关分离，沿用模型、推理强度和预算规则。ChatGPT 项目自动创建与双向同步未接通，接口不返回虚假外部聊天链接。

所有会话以此约定并行实现；必要变更由总控统一通知。

## 能力补齐 v3

- `GET /events/{id}/trace` 新增 `semantic_routing,targets,target_tasks,target_subscriptions,target_observations`。多目标母事件 task_id 允许 null；按 targets 判定投递，逐目标观察不能冒充本事件独占执行证据。
- `POST /subscriptions {project_id,task_id,source,thread_id,profile?}` 与 `DELETE /subscriptions/{id}` 管理显式订阅。每个来源事件/目标只有一个 canonical message，Worker 会话展示经 EventTarget 关联的 delivered 消息。
- `GET /routing/jobs?after=&limit=` 返回持久模型 context/output、thread_id/turn_id、decision/status/error 及实时 `correction_tasks`。
- `POST /routing/schedule {event_id?}` 检查尚无模型 job 的待确认事件。`POST /routing/jobs/{event_id}/correction {decision,evidence}` 需要完整 action/kind/task_id/state_version/reason；当前任务版本及权限重新校验，已应用事件不重投。
- `GET /operations/nodes` 返回授权节点和项目绑定；`PATCH /operations/projects/{id}/execution-node {node_id|null}` 持久选择，运行中或已有未结束线程时禁止迁移。
- `/operations/daemon/poll` 与 `/exchange` 使用专用节点 HMAC、时间窗口和持久 nonce 鉴权，独立于 Web 用户令牌。已租操作不重新派发，启动恢复先于 Scheduler 派发。
- `GET /operations/watchdog?task_id=`、`POST /operations/watchdog/tasks/{id}/run` 与 `POST /operations/watchdog/{run_id}/messages {content,reconcile_unknown?}` 提供独立巡检与纠正。巡检对账不解除 Worker 的未知写入保护。
- `GET /conversation-providers` 返回真实能力声明。`/conversation-providers/bridge/status`、`/sessions`、`/sessions/{id}`、`/operations`、`/operations/{request_key}` 使用平台 Bearer 鉴权；create/message/control 复用原会话控制，消息及控制强制 expected_state_version，幂等键持久化。
- `POST /conversation-providers/mcp` 为受鉴权的 Streamable HTTP JSON-RPC；本地 STDIO 入口 `python -m superagent.runtime.chatgpt_bridge`。ChatGPT 项目自动创建及历史同步状态为 blocked，不返回猜测的链接。
- 新设置 `semantic_routing_enabled=false`、`watchdog_enabled=false`、`watchdog_interval_seconds=60`，沿用现有模型、强度、预算预留与未知费用对账。

完整字段及验证边界见 [语义与订阅](handoffs/semantic-v3.md)、[设备与巡检](handoffs/operations-v3.md)、[会话桥接](handoffs/chatgpt-bridge-v3.md)。以上路径均带 `/api/v1` 前缀。

## 文件与运行

Python 包 `superagent`，应用入口 `superagent.main:app`。运行 `python -m uvicorn superagent.main:app --host 127.0.0.1 --port 8765`。API 前缀 `/api/v1`，JSON UTF-8；时间用 UTC ISO8601，界面本地化。错误形状 `{ "detail": "可读说明" }`。开发默认无真实连接，显式 demo 仅用于示范，不伪装真实执行。

## HTTP 契约

- `GET /health` → `{status,version}`。
- `GET /api/v1/overview` → `{counts: {状态: 数量}, active_tasks: [], pending_approvals: [], connectors: []}`。
- `GET /api/v1/projects` → 项目数组。
- `POST /api/v1/projects` / `PATCH /api/v1/projects/{id}` → 项目对象。
- 项目字段：`id,name,repo_path,base_branch,test_command,allowed_paths:[],dingtalk_chat_ids:[],redmine_project_ids:[],enabled,created_at`。test_command 仅管理员可配置的命令，不从消息拼接。
- `GET /api/v1/tasks?status=&project_id=` → 任务数组。
- `POST /api/v1/tasks` 请求 `{title,goal,project_id,kind?:"repair|analysis",acceptance_criteria?,source?:"web"}` → 任务。
- 任务字段：`id,title,kind,goal,project_id,owner_id,status,revision,state_version,control_version,outcome_unknown,source,source_ref,created_at,updated_at,last_error,codex_thread_id,codex_turn_id,workspace_path`；可增加字段但不删除以上字段。
- `GET /api/v1/tasks/{id}` → `{task,events:[],artifacts:[],approvals:[]}`。
- `POST /api/v1/tasks/{id}/messages` 请求 `{content,change_goal:false,expected_state_version?}` → 事件。
- `POST /api/v1/tasks/{id}/controls` 请求 `{action:"start|pause|resume|cancel|retry",expected_state_version?}` → 任务。
- `POST /api/v1/tasks/{id}/acceptance` 请求 `{accepted:true,comment?,revision}` → 任务。
- `POST /api/v1/tasks/{id}/reconcile` 请求 `{outcome:"stopped|abandoned",evidence,expected_state_version}`；未知执行结果由 owner/admin 明确核验，无本地活动进程后才可解除保护。stopped 进入 paused，再显式 resume；abandoned 进入 cancelled。
- 服务重启时，尚未收到确认的暂停或结束请求进入「执行结果未知」，不自动重跑或视为已停止。确认执行已退出后，可选择「确认结束此事件」关闭事件，无需渠道回复。
- `GET /api/v1/approvals` → 审批数组；`POST /api/v1/approvals/{id}/decision` 请求 `{decision:"approve|reject",action_hash}`。
- `GET /api/v1/connectors` → 状态数组，每项 `{id,name,configured,enabled,status,last_error,last_seen}`。
- `GET /api/v1/settings` → 脱敏配置；`PATCH /api/v1/settings` 仅非秘密设置。
- 设置 `dingtalk_route_all_mentions` 为布尔值，默认 false。在管理设置的运行策略中开启后，DWS 明确标识为 @本人的消息无需命中请求关键词或问句即可进入处理，未明确要求修改时使用 analysis。普通群消息继续使用请求识别，身份、项目授权及外部回复审批仍按现有流程校验。配置保存后对后续接收及重新路由生效，旧事件缺少 @本人标识时继续使用请求识别。
- `GET /api/v1/artifacts/{id}` → 可鉴权的文件或内容；不能返回任意用户路径。
- `GET /api/v1/artifacts/{id}/download` → 附件形式的完整 JSON；`GET /api/v1/tasks/{id}/export` → 持久任务、事件、审批及产物快照 JSON，不跟随任意文件路径。
- `GET /api/v1/events/stream` → SSE，前端也可有界轮询任务列表。
- `POST /api/v1/events` 为内部/本地测试注入，真实部署需要管理员身份，不暴露为未鉴权公网入口。
- 重复事件返回原记录和 `duplicate:true`，HTTP 200；不能新建第二份任务。
- `GET /api/v1/events?routing_status=pending_confirmation&after=0&limit=50` → `{items,next_after,has_more}`。管理员可 `POST /events/{id}/retry-routing` 或 `/retry-attachments`。
- 登录：`POST /auth/login {token}` 返回 HttpOnly 会话，`POST /auth/logout` 注销，`GET /auth/me` 返回 user_id/role/authentication。其余路径均带 `/api/v1`。
- 管理接口：`GET/PATCH /settings`、`GET/POST/PATCH /identities`、`DELETE /identities/{id}`（停用）、`GET /audit`、`GET /budgets`、`PATCH /budgets/{account}`、`GET /budget-reservations`、`POST /budget-reservations/{id}/reconcile {actual_micros,evidence}`。具体字段见治理交接。
- 连接启停：`POST /connectors/{name}/{start|stop}`。回复：`GET/POST /tasks/{id}/deliveries`，新草稿 `{event_id,content}`；`POST /deliveries/{id}/decision {decision,action_hash}`、`/publish`、`/reconcile {outcome,evidence}`。外部发送审批与 Codex 工具审批使用不同入口。

统一任务状态：queued/running/waiting_input/waiting_approval/waiting_resource/paused/review_ready/completed/failed/cancelled。默认人工验收；completed/cancelled 新需求另建关联任务。

## 运行时模块 契约

`superagent.runtime.codex` 提供 `CodexAppServer` 类：

```python
client = CodexAppServer(executable: str | list[str], cwd: str, config: dict | None = None)
await client.start()
thread = await client.start_thread(cwd: str, instructions: str = "")  # dict 含 id
await client.resume_thread(thread_id: str)
turn = await client.start_turn(thread_id: str, prompt: str, model=None, effort=None, image_paths=None, attachment_root=None)  # 后四项关键字参数，dict 含 id
await client.steer_turn(thread_id: str, turn_id: str, prompt: str)
await client.interrupt_turn(thread_id: str, turn_id: str)
async for event in client.events(): ...  # 原始 method/params、server request id
await client.respond_approval(request_id, decision: str)
await client.close()
```

此接口是内部封装，底层严格按本机 Codex schema 与官方文档核验。禁止默认全权限。Codex 发现、会话状态持久化由控制层配合；运行时不自行发钉钉/Redmine 消息。

`superagent.runtime.workspace` 提供 `prepare_workspace(repo_path, base_branch, task_id, workspaces_root) -> dict`（含 path/base_sha/branch），`collect_changes(path) -> dict`（含 diff/stat/status），均需路径和 Git 状态校验，拒绝默认吞掉未提交改动。runtime 额外接口以 handoff 说明。

## 接入模块 契约

统一事件字典：`{source,external_id,event_type,actor_id,thread_id,project_external_id,issue_id,content,occurred_at,attachments:[],metadata:{}}`。业务身份需映射；不得将外部正文当授权。

`superagent.connectors.redmine.RedmineClient(base_url, api_key)`：异步 `list_updated_issues(updated_since, project_id=None) -> list[dict]`、`get_issue(issue_id) -> dict`、`add_comment(issue_id, content) -> dict`、`close()`。网络超时、分页、权限和未知写结果要明确处理。

`superagent.connectors.redmine.RedminePoller(client, emit, state_store, project_ids, user_id)`：异步 `poll_once()`，emit 为 async callable(event)，state_store 提供 get/set 的适配约定由接入会话写明。

`superagent.connectors.dingtalk.DingTalkListener(executable, emit, ...配置)`：异步 start/stop，读取 DWS NDJSON，等待 ready，self-loop 过滤。`DingTalkClient` 封装按配置向明确 conversation/message 发送回复；不在开发时真实调用。

连接器不要依赖数据库具体实现；控制层负责 emit 持久化、身份、去重和路由。外部动作先持久化审批和发布账本，网络超时视为结果未知。

## 集成与验证

v4 新增 `GET /api/v1/agents/local`、`POST /api/v1/agents/local/connect {agent_id:"codex",use_existing_login:true}`。检测、现有登录和可用适配器状态分别返回；服务器选择已安装程序，浏览器不能提交任意命令或认证材料。已验证订阅账号通过运行审计记录使用，按量账号及远端设备保留预算约束。

`dingtalk_response_policy` 设置为 `{direct_messages:"reply"|"off",group_messages:"mentions"|"requests"|"off",delivery:"draft"|"approved_send",default_project_id:int|null}`。保存新策略只重配已有监听，单独启动仍走连接控制；`GET /connectors` 提供真实逐项 `scopes` 与整体 `degraded` 状态。未保存新策略的旧部署保留原监听范围。

指定群配置使用 `group_scope=selected`，`group_chat_ids` 保存已开启接收的群，`group_names` 保存群备注，`group_original_names` 单独保存钉钉群原名。旧配置缺少原名时，界面通过 `GET /connectors/dingtalk/group?chat_id=` 按群标识补取，返回 `{id,name}`，保留旧备注。关闭群时保留名称记录，重新开启时将该群加入接收列表；删除群同时移除接收标识、备注及原名，保存后生效。接收列表允许为空，表示所有指定群均已关闭。界面通过名称搜索添加群，保存消息策略后生效。

任务 `kind` 支持 `reply`，通过独立回复 Worker 运行，生成真实 thread/turn、正文、验证和来源草稿。`semantic:{event_id}` 是事件分流会话，`router:{project_id}` 是项目讨论，`worker:{task_id}` 是执行会话。会话详情包含实际角色和关联 Worker，人工消息带 `expected_state_version`。`GET /sessions/{id}/transcript` 只读取平台已绑定线程，返回 `source/complete/items/reason`，没有真实历史时明确降级，不伪造模型输入输出。具体合同见 v4 模块交接。

分析模式使用 app-server 实验动态工具：`list_files(path)`、`read_file(path,start_line?,max_lines?)`、`search_text(path,query)`。请求为 `item/tool/call`，必须属于当前任务 thread/turn；响应仅允许文本内容。路径只接受当前独立工作区内的相对路径，拒绝敏感目录、密钥文件、链接和硬链接；单文件与总输出有上限，搜索为固定子串匹配，不启动 shell 或联网。读取失败、拒绝和截断均进入证据，单独列目录不能支持分析通过。动态工具定义仅在新建分析线程时绑定；旧线程升级需新建只读线程并保留工作区和审计。

分析验收依据为同轮实际读取证据、结构化报告、无代码变更以及无未恢复错误。它不要求修复测试；代码修复仍要求当前工作区的真实测试命令证据。两者在工作台分别展示，不将只读分析的“未运行测试”误判为失败。

控制后端负责可配置 Scheduler（Codex runtime 可用时真实运行），使用连接器统一事件。其他会话仅写所有权目录；不因依赖未就绪停工，按此契约写单元/协议测试。根目录 Python 配置由控制后端所有，不互相覆盖。根 README、部署和端到端验收归总控及验收会话。


## 事件中心与事件组（2026-11-14 本轮修订）

- 产品主入口为事件中心，按事件组聚合问题，Worker 工作台展示实际会话。Task 表和旧 API 保留为内部执行记录，不迁移或删除历史数据。
- `GET /api/v1/event-groups` 返回当前用户可访问的事件组；`GET /event-groups/{id}` 返回 `{group,events,following}`。group 包含 `worker_id,event_count,pending_event_count,processing_status`。当前每组一个主 Worker，可关联多个协作子组。
- 事件组包含直接事件及 EventTarget 关联的原始事件；投递副本不重复展示。过程记录与需要核验的来源事件分开标识。`completed` 但有未解决事件时，组视图为 `needs_review`，不能把执行结束等同于事件解决。
- `POST /event-groups/{id}/events/{event_id}/resolution {status:pending|resolved|dismissed,evidence,expected_state_version}`：逐事件记录核验。新增 `event_resolution` 事件保留历史，不改写原始收件；不同事件组对同一来源的处理结论独立。
- `POST /event-groups/{id}/following/{subscription_id} {enabled,expected_state_version}`：停止或恢复既有显式跟进，不删除历史。全局订阅列表只读。问题引用关联继续由已有 Router 机制维护，不自动将群内单条消息扩大为全群订阅。
- `POST /event-groups/{id}/delegations {goal,kind:analysis|repair,request_key,expected_state_version}`：创建同项目独立子 Worker；请求键重放不重复创建。所有权、项目启用、终态和未知执行状态检查仍生效。
- Worker 可在保存的最终 JSON 中添加 `collaboration_requests:[{goal}]`。调度器从当前版本报告消费，最多创建三个只读子 Worker；子 Worker 不自动递归。修改型委派通过明确的界面操作完成。
- 子 Worker 形成结果或失败后，追加 `collaboration_result` 到原组。结果进入主 Worker 后续输入。运行中、等待审批、等待资源或未知状态不强行推进；暂停/结束组只保存结果。其他可恢复组重新排队并更新版本、使旧审批过期。
- Router 的语义规则强调同一问题的补充/纠正/反馈优先关联现有组，不仅凭同群或同人合并；现有身份与版本校验保留。内部协作结果使用确定性处理器回流，不声称每条内部事件都调用模型 Router。

## 2026-11-15 项目与自动交付扩展

- 项目新增 `repositories:[{path,base_branch}]`，path 为根目录下的仓库相对路径。空数组保持原有单仓库行为。独立工作区事件的 base_sha 在多仓库模式保存为仓库路径到提交 SHA 的映射。
- `DELETE /projects/{id}` 隐藏归档项目并停用，保留内部编号及历史任务。
- `GET /project-workspace?path=` 返回当前目录、父目录、子目录、Git 本地分支及当前分支，受管理员权限和服务端目录范围约束。`GET /project-workspace/codex-projects` 只读本机已保存的 Codex 项目名称与目录。
- `POST /project-workspace/select-directory {path?:str}` 在本机 Windows 桌面打开系统文件夹选择窗口，返回 `{path:str|null}`，取消时为 null。需要项目配置权限和回环地址访问，选中路径继续校验服务端目录范围。同一时间只打开一个窗口，180 秒超时关闭。系统窗口不可用时，界面提供网页目录浏览入口。
- `dingtalk_response_policy.delivery` 新增 `auto_send`，作为钉钉和 Redmine 当前结果自动交付模式。须同时启用 external_delivery_enabled 和对应连接器。自动授权、失败和发送结果持久记录，发送前重新检查规则与版本。
- `GET /events` 新增 source 和 q，先筛选再分页。`GET /event-groups/index` 新增 source 和 status，筛选聚合事件后分页。
- Redmine 轮询的工单响应包含布尔值 `status.is_closed` 时，事件保存为 `metadata.issue_is_closed`。当前工单已关闭、无备注和附件，且仅属状态变更及附随自定义字段变化的日志，保留在「已结束」，不进入项目分派或创建 Worker。未知关闭状态、重新打开、有备注、指派变更或附件变更沿用原规则。
- 事件中心列表支持 `status=needs_action`（`review`、`attention`）及 `status=finished`（`completed`、`closed`）。聚合筛选先于分页；`counts` 仍按原始状态返回，统计范围受搜索、项目和来源限制，不受当前状态按钮限制。
- 连接器状态新增 missing_configuration，启用配置保存时尝试首次连接。设置响应新增 service_mode，独立预览为 preview。

## 2026-11-15 取消恢复与回复续查

- `POST /tasks/{id}/controls` 的 `resume` 支持 cancelled → queued，递增需求版本与控制版本，保留原记录。未知执行结果和仍活动的进程继续阻止恢复。
- 同接口新增 `analyze`，仅允许已停止或已形成答复的 reply Worker 转为只读 analysis，递增需求版本，清除工具受限的回复线程绑定。既有回复与发送账本保留。
- 私聊项目进展询问进入只读分析，语义分派选择 reply 时仍保留分析能力。问候与普通对话沿用回复模式。
- 事件详情以最新执行状态更新状态条，渠道回复直接显示尚未回复、已回复或待核实是否已回复。未知发送必须主动选择核实结论并填写证据。

## 2026-11-16 事件结束与回复判断

- `controls: cancel` 支持已验收的 Worker，保留执行结果和原始消息核验状态。事件中心统一用 `status=finished` 查看已完成和已关闭；保留 `status=closed` 查询兼容。
- 自动回复复用当前执行轮次。模型根据北京时间、原来信及可见的后续发言和配置判断 `send / skip / review`，判断依据在事件内保留。分析和修复仅在本轮结果通过核验后产生渠道草稿；「改为只读分析」及跨目录参考结果仅留在工作台。
- `auto_send` 只发送本轮判断绑定的渠道草稿；历史摘要和人工另写的草稿不会自动发送。发送前检查来源、当前版本、已知人工跟进、重复和未知发送结果、渠道权限及实时规则。回复型事件在渠道确认或模型判定无需回复后可进入「已结束」，不改变原消息核验状态。
- `dingtalk_response_policy` 可保存 `reply_guidance`（可选，最多 1000 字）和 `reply_max_age_minutes`（默认 120，1–1440 分钟）。事件规则新增 `reply_quiet`（北京时间起止小时，支持跨午夜），仅暂停自动发出；过时的候选不会补发。既有 `review` 优先于自动发送。

## 钉钉私聊续办

- 钉钉接入读取最近活跃私聊中的本账号发言。来信分流前做一次有时间上限的历史补收。同步通过原消息和账号验证，优先使用引用或紧邻的同私聊来信确定归属，重复收到时复用原事件。
- 启用语义路由时，无明确引用的私聊续消息进入研判，候选包含有权限的在办事件及近期已完成事件。默认项目回退时，可从同一私聊的其他已授权项目选原事件。相同发送人或会话仅提供背景。
- Router 可以选择 `context` 并引用当前可用的任务及版本。该动作只写消息记录，消息以 `context_only` 在事件「消息」页展示，供后续轮次使用。有效补充走既有任务版本和 Worker 退出确认流程。
