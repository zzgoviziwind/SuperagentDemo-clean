# 飞书私聊卡片审批

卡片模式仅覆盖在线 Worker 的文件修改和命令执行审批。只发给绑定的负责人。卡片展示任务编号、审批编号、操作类型和权限范围，支持批准或拒绝并二次确认。命令权限范围是隔离工作区；卡片不发送命令参数、业务原文或绝对路径。认为信息不足时选择拒绝。

点击后，飞书回调验证应用、点击者及消息与审批记录是否相符，并核对负责人、任务状态和版本。工作台与卡片复用同一审批执行路径，决定通过后通知原 Worker；结果用原卡片显示，已处理的卡片不再提供操作按钮。重复点击不会重复发出决定。飞书回调的即时提示「正在提交」不代表审批已成功，原卡片的最终结果以 SuperAgent 保存的状态为准。

## 启用

1. 飞书后台保留应用范围仅本人、应用身份发消息权限，以及「使用长连接接收回调」和新版「卡片回传交互」`card.action.trigger`。这些飞书配置需要发布新版本才会生效。
2. 在主服务使用的 Python 环境安装可选依赖：`uv pip install --python .\.venv\Scripts\python.exe -r requirements-feishu.txt`。容器部署需在镜像中安装相同依赖。
3. 在启动进程的受保护环境填写 `SUPERAGENT_FEISHU_APP_ID`、`SUPERAGENT_FEISHU_APP_SECRET`、`SUPERAGENT_FEISHU_OPEN_ID`（同一应用下的本人 `ou_…`）、`SUPERAGENT_FEISHU_OWNER_ID`（实际任务负责人，单用户默认账号通常是 `admin`）。设 `SUPERAGENT_FEISHU_MODE=card` 与 `SUPERAGENT_FEISHU_ENABLED=1`。无需对手机开放工作台或配置公网回调 URL。
4. 停掉之前的临时连接检查窗口，再启动卡片版主服务。不要同时保持同一应用的检查连接和正式连接。预览仍禁用真实飞书，正式模式在长连接建立后才会发送卡片。
5. 用专门的隔离测试任务验收：只给设置的收件人发一张卡片；分别验证批准、拒绝、重复点击、任务版本变化及 Worker 继续。检查卡片最终状态，没有收到最终状态时核对任务，不重复提交未知结果。

兼容性：飞书 Python SDK 1.8.0 的长连接客户端会忽略 CARD 类型数据帧。本项目在原 SDK 鉴权和接收流程中补齐 CARD 的分派与应答，依赖锁定到这一版本，升级时需重验帧处理。
