# 无人值守：默认继续，例外请人决策

目标：人不用定期打开工作台巡检。可在当前授权内安全完成的工作自己推进；确实需要人提供信息、作出选择或授权时，主动联系负责人。自动完成、人工验收和外部交付分别记录。

## 决策规则

| 情况 | 默认行为 | 什么时候通知 |
| --- | --- | --- |
| 已明确项目和范围的只读排查 | 查证、保存结论及限制；核验通过后自动结案 | 有影响结论的关键证据且系统无法取得，说明需要补什么 |
| 已授权的隔离修改和测试 | 自行修改、复测、收集变更与回退说明 | 超出授权、验收证据无法补齐，或下一步需要合并、部署、写业务数据等权限 |
| 新来信补充同一要求 | 新版本接手；旧结果、旧审批失效；如需停止旧执行，确认停止后再续跑 | 项目、目标或授权发生冲突，或者无法确认旧执行是否已停止 |
| 暂时性资源故障 | 有界退避重试；只自动重试已知无副作用或有幂等保证的动作 | 重试耗尽且需要人恢复环境；不为每次失败提醒 |
| 自动回复 | 只有项目策略允许、已核验、原渠道与当前版本均匹配时自动发送 | 规则要求审核、目标不明确或存在冲突；明确无需回复可直接结束 |
| 外部操作结果未知 | 优先查账或查渠道确认，保留阻断 | 无法核实时请人核对；不猜测失败、不盲目重发 |

「待审核」不能只由任务状态推断。区分待补资料、待选择、待授权、待核对；暂时重试、人工主动暂停、正常结束不生成决策通知。模型可整理证据与建议；规则依据结构化证据与当前授权放行，模型判断不能扩大权限。保留明确配置为人工验收的项目规则。

## 通知闭环

1. 仅在产生有效待决事项时，与等待状态一起持久化。记录负责人、项目、任务及版本、阻塞原因、建议、可选操作与有效期。现有仍有效的待办可在启用时去重补录。
2. 首选配置并验证过的负责人钉钉私聊，使用独立通知通道。现有原消息回复入口不复用为通知；没有可用收件人或发送权限时保留可见故障，不回退到业务群或原发言者。
3. 消息写清「哪件事、为什么停、现在要你决定什么、建议选哪项」，附登录后的工作台直达入口，不附敏感原文，也不在链接中携带审批凭据。工作台处理前再次校验权限、版本和待办有效性。
4. 同任务、同版本、同一决策只通知一次；仍未处理时可配置一次提醒。已知发送失败可退避重试，结果未知先核对。任务已取消、已处理或被新版取代时，取消尚未发送的提醒；旧链接显示已失效。决定生效后原任务继续或结束，无需再手点启动。

## 实现与验收

先统一后端的决策分类及通知记录，用模拟私聊验证闭环；再接收件人配置和工作台直达链接；最后用单独授权的测试收件人确认钉钉真实送达。代码入口：`scheduler.py` 处理执行、审批与验收，`ingestion.py` 和 `subscriptions.py` 处理新需求续跑，`watchdog.py` 处理巡检，`delivery.py` 保留原渠道发布及未知结果核对。

验收以完整场景为准：只读任务在无人在线时完成且零提醒；运行中收到无冲突补充后只执行新版；高风险操作暂停并通知一次，点开处理后自动继续；旧版本决策无法生效；服务重启不重复通知；结果未知不盲目重发；收件人未配置不误投。试运行记录自动完成数、人工决策数、重复提醒数和漏提醒数，逐条复核可以由系统解决却仍然打扰人的案例。

本记录为源码核对后的实施交接。通知能力尚未实现或送达验收；未改运行代码、连接配置或真实渠道。
