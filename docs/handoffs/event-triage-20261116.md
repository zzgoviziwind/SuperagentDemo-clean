# 事件研判、关闭和手动关联

- 事件中心区分未分派的消息与已分派待审核的事件。业务筛选为待研判、待人工处理、处理中、需关注、已完成、已关闭。「待人工处理」包括已分派事件的补充、审批与验收；暂停、阻塞或结果未知归入「需关注」。数量按当前来源和关键词在分页前统计；「全部」中的已关闭项排在其余事件之后。
- 钉钉的短确认与可明确识别的考勤通知自动归为无需处理；有明确事项引用、含附件、内容不明确的消息仍走正常判定。旧收件只在事件中心投影层应用这两类明确规则，不批量改写历史。
- 同一账号和会话内的回复引用，以及同一 Redmine 服务的问题编号，可将未分派消息合到一张卡片。已分派后的后续处理继续走来源引用和授权检查。语义分派开始前刷新候选事件，使排队的后续消息能定位前一条刚建好的事件。仅凭发送人或群名不合并。
- 管理员可关闭所选未分派消息、关联到可补充的已有事件，或指定项目和处理目标后新建事件。原消息及审计保留；人工关联追加正文到 Worker 后续输入，所选消息不作为渠道发送目标，附件信息保留在原始记录中。本次手动关联不自动下载附件。
- 已分派事件支持将单条消息标为无需处理；当前无需继续的事件可关闭。运行中、审批中或未知结果仍走原有停止和核验路径。

接口：`GET /api/v1/event-groups/index` 增加 `counts` 和每项的业务 `state`；`status` 接受这些状态。 `GET /event-groups/triage-options` 返回可选项目和事件；`POST /event-groups/triage` 接受 `action: close|create|link` 及所选 `event_ids`，关联已有事件必须提交该事件的当前版本。关闭后的收件不再进入重试或排队分派。

验收：164 项相关后端回归通过，最后的明确引用改动另外通过 6 项关联回归。事件中心前端 5 项测试、前端构建和独立模拟预览通过。工作区全量前端测试还有 10 项因测试环境缺少弹窗的 `showModal` 而失败。未更新主服务，未接入真实渠道。
