# 无项目事件登记与 Codex 研判

- 事件中心用原始来源记录的 ID 登记待研判事项；项目和 Worker 可以为空。人工指定项目或关联已有事件后，原始记录继续作为来源证据。
- 开启语义分派时，已通过接入检查却找不到项目的钉钉私聊可启动独立只读 Codex 研判。初始输入为同账号、同会话的有限近期消息及允许访问的项目。Agent 可按需调用 `chat_evidence` 和 `source_image`。连接器仅按已核实的账号与消息锚点取证；模型不持有凭据，也不能选择读取范围以外的会话或消息。
- Codex 输出项目建议、待补充信息或不属于项目，并记录依据。系统验证建议的候选范围和证据编号。仅凭模型建议不创建项目执行任务；管理员可接受建议并安排处理，也可保持无项目状态。
- 图片占位文本不作为路径或 URL 使用。按原始会话及消息编号获取媒体，校验附件后再将本地图片交给 Codex。手动关联图片消息同样准备附件，多图任务等待当前版本附件准备完成。
- 管理员可通过 `POST /api/v1/routing/assessments` 核查同一私聊 2 至 5 条未分派来源记录。对照研判返回关系、项目建议、工具取证明细和 Codex 会话编号，写入审计记录，不重放消息、不应用路由结果。
- 实测工具返回的图像数据有时未进入模型视野。已下载的图片按原消息与哈希去重，用原生图片输入在同一个 Codex 会话续判。最终采纳续判输出，工具记录和图片轮次分开保存。
