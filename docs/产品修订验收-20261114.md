## 总控真实模型验收

使用本机实际 `Codex 0.167.0-alpha.4.1`，账号验证为 `authenticated / chatgpt`。隔离预览中明确标注“本地注入来源”，不把注入事件称为真实钉钉来信。模型调用、线程保存、恢复和读取均使用真实程序，没有替身。

1. 注入事件 5，请求用文字说明 Router 与 Worker 的职责。实际程序检查后进入语义队列。
2. Router `semantic:5` 调用真实模型，返回 `create + reply`，理由为群聊中存在明确文字问答请求，无需调查或执行操作。
3. 系统创建 Worker 2，真实模型生成答复，任务进入 `review_ready`，产生 1 条回复草稿；原始可见记录读取 `complete=true`。
4. 在 Router 会话中补充复核要求，在 Worker 会话中要求压缩为一句话。两者分别复用原线程完成第二轮。事件仍只关联 Worker 2，没有重复创建任务。
5. 注入两条私聊消息，均进入 Worker 3，第二条自动复用原线程。生成新版本答复与草稿，草稿关联第二条实际来源事件。
6. 关闭私聊策略后注入新消息，该消息被 `ignored`，没有创建或继续 Worker。恢复原策略。
7. 最终加载修订后，事件 27 再次沿用私聊 Worker 3 完成第三轮。实际过滤证据包含解析身份 `admin`、生效回复策略、默认项目来源与逐项授权通过结果；完成后立即读取真实线程成功，得到三轮可见记录。最新草稿准确关联事件 27。

真实 Router 线程为 `01a1d83f-0535-7432-b1c1-37a9d1713c72`；真实私聊 Worker 线程为 `01a1d845-e4c3-7ac3-9756-74f95aac05a0`。这些是模型实际返回并保存的标识，不是生成的跳转链接。

本机证据保存在 `.test-tmp/v4-connect/result.json`、`.test-tmp/v4-real-flow/result.json`、`.test-tmp/v4-real-flow/followup.json`、`.test-tmp/v4-real-flow/final-proof.json`。包含来源标记、Router 决定、实际线程记录、回复草稿及关闭策略的结果；不包含认证材料。

## 验收发现并修正

- 订阅投递后的回复必须引用最新来源消息，不能继续关联旧消息。
- 草稿模式在后端禁止发布；“批准后可发送”仍需要逐条审批。
- 私聊和群聊的配置必须对应两个实际监听范围；一个范围失败时显示部分故障，不能宣称全部在线。
- 真实任务刚完成时，执行连接可能正在关闭。线程读取增加独立只读连接重试，读取失败不重放模型任务。
- 规则证据需保存本次实际解析的身份、策略和授权值，不能只拿最终结果或持久设置反推。
- 用户输入、AI 判断和执行答复分别展示；原始结构化记录可展开核对。

## 明确边界

- 真实钉钉和 Redmine 的接收、发送没有在本轮开启；预览中所有外部连接和发送保持关闭。真实渠道验收仍需在选定测试账号与会话中进行。
- 当前接通的是本机 Codex app-server 与 SuperAgent 会话界面。自动在指定 ChatGPT 网页项目创建原生聊天并双向同步仍无本轮已验证接口；MCP 桥接保留在高级入口，不等同于原生项目同步。
- 回复 Worker 使用独立空目录、只读模式、拒绝工具请求并检查原生工具活动；不宣称它构成操作系统层完全无工具隔离。
- 私聊断线历史回补、Claude 执行适配器、独立远端机器部署与 PostgreSQL 并发不在本轮已完成验收范围内。
- 旧模拟项目继续保留并明确标注。旧记录缺少真实线程时显示记录不完整，不伪造历史。
