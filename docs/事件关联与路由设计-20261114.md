# 事件、任务与会话设计（2026-11-14）

本轮以 DeepSeek 原文双层架构和事件驱动为依据。原文来源见 `架构与产品工作台.md`，本机保存正文中的注释不作为要求。

## 统一设计

事件是不可覆盖的来源事实，任务是工作目标，Worker 是任务的执行会话。一个任务可接收多个来源事件，一个事件可按订阅投递多个 Worker；页面必须分别显示历史分派与任务当前执行，不能用任务完成状态推断每条事件都已执行。

消息标题显示渠道及群名/联系人，正文保留发送者、内容和时间；缺失名称展示原始标识，不编造名称。事件详情采用与架构总览一致的 Trigger、两级过滤、Subscription/Fast Path、Router/Slow Path、Worker、执行环境、会话存储、多信道交付、Watchdog。只有存在证据的路线高亮，停止、跳过、未知分别标记。每个分派节点显示目标任务和 Worker，可直接进入会话。

Worker 会话展示真实 Codex 可见历史，按轮次呈现消息、执行时间、工具调用及结果的展开详情。历史不完整或无时间证据时明确显示，不估算为真实耗时，不展示隐藏推理。

## Router 生命周期

原文实践是常驻 Router Session 配合批处理，也明确允许 Router 层由多个会话或工程逻辑实现。本项目采用项目级持久协调会话和逐事件判定线程：前者保存跨任务协调，后者保留具体事件决策证据。订阅命中走工程直通。该实现属于架构变体，不能宣称已经实现原文的单会话批处理或定期自动压缩。

## 跨来源协调

Worker 内和项目 Router 内均可提出结构化关联请求，由统一协调入口处理。已接收事件可在权限、任务状态、版本及幂等校验后关联目标任务；保留原始来源和旧分派，不把关联解释为删除或静默取消其他任务。订阅未来事件应与补投历史事件区分。

未捕捉事件记录准确来源引用和获取请求；只有真实取得原始内容后才能作为来源事件。请求登记不能冒充获取成功。模型或外部消息不能绕过确定性权限校验。界面显示申请、应用、拒绝和待获取的实际状态及理由。

## 验收门槛

验证一任务多事件、多 Worker 投递、规则直通、模型分流、拦截/缺证据、来源名称缺失、Worker 跳转、工具历史展开、协调申请与应用、越权/版本冲突/重复应用。测试使用离线模拟来源，真实钉钉与 Redmine 收发另行标记；不发送真实消息、不部署、不提交现有混合工作区。
