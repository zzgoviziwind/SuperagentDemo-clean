## 已实现

1. 事件详情复用完整架构图，覆盖订阅直达、路由、多 Worker、环境、存储和守护；蓝线叠加实际接入分派记录，节点区分本事件证据和关联任务当前状态。未记录不等于已执行。
2. 三类页面采用统一关联导航样式。任务跳转查询来源事件，会话切换同步导航目标。
3. 架构状态说明明确为分类而非必经阶段；回复、分析、修复均可能进入等待验收，对外发送单独审批。
4. 回复 Worker 恢复原线程时只传入新增消息；成功答复记录输入事件游标。旧记录按已完成轮次开始边界兼容，避免漏掉执行期间的新消息。新线程可携带历史背景，原线程不重发助手答复。
5. 任务和会话页不再挂载真实线程全文，只展示原 Codex 会话编号及平台消息。
6. 人工接管改为按钮，展开自动执行原暂停、核验和材料准备流程，支持收起。展开前说明暂停效果。
7. 任务事件改用业务名称和折叠技术详情；历史版本产物折叠，当前版本无产物时明确提示。

## 状态与群聊问题的含义

- 需要介入：等待补充、等待工具审批、暂停、失败或未知结果；并非需要接入账号。
- 等待验收：模型已产生结果等待人工确认；确认结果不自动表示对外发布。
- 群里单纯反馈故障不构成修改授权。是否接收受群聊策略、身份、项目绑定、规则和意图判断影响；明确分析请求进入分析，明确修复请求才允许修复。语义模型不能自行扩大成写代码权限。
- 回复任务仅基于现有内容回答，不能声称查过日志或改过代码；缺少证据应请求补充或另建分析任务。
- 平台完成、回复草稿、批准发送、发送成功是不同状态，需要分别查看。
