# SuperAgent：事件与会话工作台

更新：2026-11-14。本文定义本轮重构的产品入口、真实执行边界和后续扩展位置。

## 产品定位

SuperAgent 管理工作请求、来源、项目、订阅、会话、执行证据和交付。Codex app-server 提供代理执行能力。平台内能够查看上下文、补充事实、改变任务目标、暂停执行和核验未知结果。

首页按架构展示系统；事件中心回答“发生了什么、为什么在这里停止”；会话工作台回答“代理收到了什么、说了什么、如何纠正”。任务页保留差异、测试、审批、验收和外部回复。

## 事件追踪原则

一条事件保存来源、外部编号、发送者、讨论引用、原始内容以及处理尝试。每次重新路由追加独立尝试，不覆盖上一轮失败。重复接收返回原记录，不新增任务或伪造处理尝试。

阶段状态为“通过、阻止、跳过、待处理、未记录”。新记录来自后端真正执行的检查。旧事件缺少逐阶段证据时标记历史记录缺失，不能根据最终任务状态反推所有步骤通过。

订阅匹配先于新请求关键词检查，已有未结束任务的“这里还有一个截图”等补充可跟随原任务。身份、项目授权、引用冲突和任务所有权仍需校验。任务已结束后的普通致谢不能开启新修复任务。

路由尝试描述当时的决定；执行证据描述当前关联任务。界面明确分开，两者不能互相替代。发送草稿和发布结果按来源事件精确关联。运行事件和产物是任务级证据，不能声称每条均由当前选中的来源事件触发。

多目标事件有唯一来源记录，另为每个 Worker 保存投递关联与独立消息。母事件没有单一 task_id 也可以已经投递；界面逐目标显示执行和巡检状态。模型分派明确记录模型判定或人工纠正，不伪装成规则路由。被忽略或判定失败的消息可由管理员提供证据纠正；已应用事件不会二次创建任务。

## 会话与人工介入

- **Worker**：在会话页发言会复用现有任务消息接口。普通补充在运行时尝试送入当前轮次；改目标使旧结果与审批失效并停止旧执行。版本冲突提示刷新，未确认送达和结果未知均不会自动当成成功。进入任务页可暂停、继续、取消及验收。
- **事件 Router**：`semantic:{event_id}` 对应真正作出分流判断的 Codex 会话，保存实际输入、可见输出、分流理由和应用结果。人工复核复用同一线程；已经分派的事件只讨论，不重复建任务。规则直通时明确标注规则，不编造 AI 会话。
- **项目讨论**：`router:{project_id}` 保留项目级讨论。它与事件 Router 分开命名，不能把普通讨论当作分派证据。真实路由输入包含授权任务摘要、近期结果和订阅关系，提供共享项目上下文。
- **恢复**：Router 断线或服务重启遇到运行状态时标记结果未知，保存线程和消息。管理员提供核验说明且本地运行已退出后解除保护；旧请求不会自动重播。
- **内容边界**：仅展示用户消息、可见助手答复和经过选择的执行证据；不以模型隐藏推理作为日志。外部输入不能通过伪造事件类型冒充助手答复。

Router 使用 app-server 的只读模式、独立目录和选定的 Codex 账号。回复 Worker 同样使用空目录和只读模式，拒绝工具请求并检查原生工具活动；协议仍可能暴露内建工具，因此不把此流程宣称为操作系统层完全无工具隔离。可见历史不包含模型隐藏推理。

## 配置入口

默认只呈现三步：“选择本机 Agent”“接收哪些消息”“结果先审后发”。本机扫描区分安装、登录和适配器支持；只有支持的 Agent 可选。Codex 复用已有登录后即可启用执行，Claude Code 目前仅检测安装，不宣称已接通。

钉钉私聊默认回复，可关闭；群聊可选仅 @ 我、识别工作请求或关闭。项目与发送者授权仍有效。私聊和群聊通过两个真实监听范围接入，逐项显示健康状态；策略修改只重配已运行的监听，保存设置本身不启动消息接收。草稿模式在发布入口禁止发送；批准后发送模式仍需逐条批准。DWS 单聊历史恢复尚未实现，不将群聊历史冒充私聊记录。

Router 模型讨论开关 `router_agent_enabled` 与 Worker 自动执行开关 `scheduler_enabled` 独立。显式选择并验证本机 ChatGPT 订阅账号后，按账号实际额度执行并记录运行审计，无需金额预留；按量账号仍要求有效预算和正数单轮预留。没有真实价格依据时保留预算待核验，不将 token 数或订阅额度伪装成实际费用。

`semantic_routing_enabled` 控制新来源事件的模型分派，连接可用本机账号时启用；`watchdog_enabled` 与 `watchdog_interval_seconds` 控制独立巡检，需另行开启。执行设备的授权项目、目录和令牌环境变量由服务端配置，界面选择已授权设备；绑定设备离线时等待资源，不悄悄切回本机。

## ChatGPT 应用接入

官方 [Codex app-server](https://developers.openai.com/codex/app-server) 支持持久线程、继续轮次、执行中引导、可见事件与审批；[Codex 平台说明](https://developers.openai.com/blog/codex-as-a-platform) 明确支持应用围绕该运行时构建自己的界面。这是本轮采用的可调用接口。

本次开发环境提供的 ChatGPT/Codex 应用内建聊天工具属于当前客户端能力，不能直接当作 SuperAgent 服务的已发布接口。此次没有验证到可由独立服务自动创建指定 ChatGPT 项目聊天并双向同步的公共调用契约，因此没有生成虚假的 ChatGPT 链接，也没有复用浏览器登录态进行自动化。

平台现提供 STDIO 与 Streamable HTTP MCP 桥接：客户端可查询会话、创建分析任务、续聊、读取可见历史与控制 Worker，全部复用同一套权限、版本检查及持久幂等账本。界面显示实际能力和阻塞原因，未伪造外部会话链接。桥接把客户端作为平台操作入口，不等于平台任务自动成为 ChatGPT 项目内的原生聊天，也不提供自动历史同步。

支持本地 MCP 的桌面客户端可启动 `.venv/Scripts/python.exe -m superagent.runtime.chatgpt_bridge`，令牌只通过环境变量传入。ChatGPT Web 接入仍需 HTTPS、OAuth 服务及账号安装验收；本轮没有公开服务或安装真实账号应用。完整说明见 [ChatGPT 桥接交接](handoffs/chatgpt-bridge-v3.md)。

## 本机预览与验证

在项目根目录执行 `.\deploy\start-preview.ps1`，打开 `http://127.0.0.1:8876`。独立后台进程使用 `data/preview-service/database/preview.db`，只绑定本机，渠道、执行和模型默认关闭；退出当前终端不会结束预览。停止用 `.\deploy\stop-preview.ps1`。它不替换原 `8765` 工作台或真实业务数据。

运行后端验证：`.venv/Scripts/python.exe -m pytest tests -q`。前端在 `apps/web` 执行 `npm test` 和 `npm run build`。Windows 运行环境需允许 Python 异步循环使用本机回环连接，否则 `asyncio` 初始化可能阻塞，不能据此认定业务测试通过。

实际检查结果记录在 [能力补齐验收](能力补齐验收-20261114.md)；[第一轮验收](重构验收记录-20261114.md) 保留当时的完成范围与问题。
